## 1. 为何否决 V1（Handlike）并改走 FS

### V1 结论

区域聚类 + 无抖动 + 色相锁定等，在人像试点上**整体不如预期**：

- 易海报化过硬（左右脸 mag 成两套色相、嘴成单色块）  
- 「像手绘」的结构保留不稳定，调参收益递减  
- 与用户可接受的观感距离仍大  

→ **否定为产品主方案**；代码与文档保留，供对照与局部思路复用（如 Lab、色预算、去孤点），**不再作为迭代主线**。

### 为何回到 FS

现网 / 竞品主流是 FS，原因成立：

- 能用邻格混色表达中间调，人像光影不断崖  
- 实现成熟，用户已有心智（本站已有 FS 选项）  

V2 不是「再写一遍教科书 FS」，而是承认：

> 默认 FS 对**屏幕半色调**合理，对**近看一颗一颗的拼豆**噪声与色数膨胀过重。

V2 = **FS 骨架 + 拼豆约束**。

## 2. 目标与非目标（产品合同 · 0.9 起）

迭代只对照下面三点。调参、模式、补丁若对不上这三点，一律视为跑偏。

### 目标（仅此三项）

| # | 目标 | 像素区域 | 做法 |
|---|------|----------|------|
| 1 | **强化线条** | `LINE`：结构边 / 描边 | 墨\|填二元；线条附近贴主色块，禁止灰泥第三色；扩散切断 |
| 2 | **去抖动色** | `FLAT`：大色块内部 | 近零扩散 + 邻格粘滞 + 去碎点；消灭椒盐跳色 |
| 3 | **平顺过渡色** | `SHADE`：阴影 / 高光缓变 | **保留** FS（强度≈经典）；色度可跟，明度阶连续 |

同一张图上三种区域并存：卡通以 LINE+FLAT 为主；人像以 FLAT+SHADE 为主、五官处 LINE。

### 非目标

- 不再以「平面检测对错」或「比经典 FS 少几个色」为成功标准  
- 不替代出图后人工修图  
- 不引入深度学习分割  

### 成功标准（验收）

| 目标 | 怎么看 |
|------|--------|
| 1 线条 | 描边/外轮廓可读；线侧不应出现成片灰/脏色，应落在墨或邻域主色 |
| 2 去抖 | 大色块内无明显椒盐、无随机第三色条带 |
| 3 过渡 | 脸侧光、嘴角阴影仍有柔和阶变，不像海报色块 |

未达三点可接受前，不撤经典 FS 默认。

## 3. 问题归因（经典 FS × 拼豆）

| 现象 | 机制 |
|------|------|
| 皮肤盐胡椒、色过多 | 全强度误差扩散 + RGB 近邻在稠密色板间抖动 |
| 边缘发毛 | 误差跨过强边推到轮廓外 |
| 阴影脏灰绿/脏橙 | RGB 距离 ≠ 感知；暗部近邻偏色 |
| 小结构糊 | 扩散 + 无结构保护，唇/眼被邻色吞 |
| 左右「假色差」 | 暗亮两侧落到不同色相族（V1 也踩过，FS 里同样会出现） |

V2 逐条加约束，而不是换一套无抖动哲学。

## 4. 方案提纲（管线）

输入：已缩放到棋盘的 `ImageData` + 色板（与现网一致）。

```text
① 预处理（可选，默认轻）
     - 对比度/饱和度仍由工具层现有逻辑负责，V2 内核不重复
② 色板准备
     - Lab（或 OKLab）索引；可选：按预算预筛工作子集（maxColors）
     - 肤色锚点（全图皮肤采样中位 a*/b*）——仅影响「判为皮肤」像素的选色
③ 结构图（轻量）
     - 梯度 / 边权：用于调制扩散强度与是否跨边扩散
④ 自适应 FS（核心）
     - 蛇形扫描（可与现网一致）
     - 选色：感知距离；皮肤像素 → 色相锁定后再近邻
     - 误差 × strength(x,y)：平坦区↓、缓变区中、强边附近↓或 0
     - 跨强边：扩散权重削减或切断（edge-aware FS）
⑤ 轻后处理（可选开关）
     - 仅删「面积 1 且与 8 邻域众数 ΔE 小」的碎点
     - 禁止大面积并块（避免滑回 V1 海报化）
⑥ 输出 ImageData / grid id
```

### 与经典 FS 的关键差异

| | 现网 FS | FS V2 |
|--|---------|--------|
| 选色空间 | 加权 RGB | Lab / 感知 + 皮肤 hue lock |
| strength | 全局常数（如 0.85） | **空间自适应** + 边感知 |
| 色数 | 被动用满色板 | 可选预算子集 + 扩散仍在子集内 |
| 后处理 | 无 | 极轻去碎点（保守） |
| 代码位置 | `image-utils` | **独立** `bead-fs-v2.js` |

## 5. 模块与 API（落地规格）

### 文件

- `index/js/bead-fs-v2.js`  
- 导出：`window.FGBeadFsV2` + CommonJS  
- `version()` → 自 `0.1.0-fs-v2` 起  

### API（建议与 Handlike 对齐，便于切换）

```text
quantizeImageData(imageData, paletteColors, opts) → ImageData
imageToGrid(imageData, paletteColors, opts) → { cols, rows, grid }
version() → string
```

### 建议 opts（实现时可微调，改文档同步）

| 键 | 建议默认 | 含义 |
|----|----------|------|
| `maxColors` | 0=不限制 | >0 时先把工作色压到 N 再 FS |
| `strength` | 0.85 | 对齐经典 FS |
| `flatStrength` | 0.48 | 仅深平坦略低于经典 |
| `shadeStrength` | 0.9 | 阴影/高光过渡（≥经典） |
| `edgeStrength` | 0.4 | 结构边 |
| `edgeCut` | true | 仅强色度边轻削减（×0.55） |
| `skinHueLock` | 0.35 | 皮肤 ab 锚点（减弱，避免假色相硬边） |
| `skinHueSlack` | 16 | 皮肤选色 ab 半径 |
| `flatGrad` / `shadeGrad` / `edgeGrad` | 3 / 4 / 28 | 更早进入 shade 扩散 |
| `chromaEdge` | 12 | 结构边阈值 |
| `skinChromaBleed` | 0.55 | 皮肤色度扩散（0.5 起更顺滑） |
| `chromaBleed` | 0.95 | 非皮肤 |
| `errorClamp` | 72 | 误差钳位 |
| `stickyFlat` | true | **仅**深平坦粘滞 |
| `chromaSmooth` | true | **仅**深平坦肤色平均 ab |
| `featureProtect` | true | 唇/暗坑保护 |
| `featureBleed` | 0.95 | 嘴边近经典扩散 |
| `contentMode` | `auto` | `auto` / `photo` / `flat`（卡通平面） |
| `snapEdges` | true | 高梯度格吸附邻域众数（去抗锯齿脏边） |
| `despeckle` | 1 | 后处理强度 0=关 |
| `alphaCut` | 16 | 透明阈值 |
| `serpentine` | true | 蛇形扫描 |

工具接线（实现阶段）：`dither === "fs-v2"` 或新预设「FS 优化（试点）」→ 只调 `FGBeadFsV2`，经典 FS 保留对照。

## 6. 分阶段落地（实现时按序）

### Phase A — 最小可对比

- Lab 近邻 + 蛇形 FS + 全局 strength  
- 与现网 FS 同 UI 可切换  
- **验收：** 肤色脏点是否减轻（感知选色）

### Phase B — 自适应 + 边感知

- 梯度图调制 strength；跨边扩散削减  
- **验收：** 五官/发际毛边是否少于经典 FS；平坦区是否更干净

### Phase C — 皮肤 hue lock + 色预算

- 锚点 + 预算子集  
- **验收：** 左右脸「假色相分裂」是否缓解；用色数是否下降

### Phase D — 保守去碎点

- 仅 1 格且低 ΔE 碎点  
- **验收：** 不出现 V1 式大色块嘴/海报脸

每阶段合并前更新本文 Changelog，并保留经典 FS 为默认直到产品签字。

- 未达标前默认仍为经典 FS。

### 0.2.0-fs-v2 · 2026-10-22 · 阴影过渡

- **问题：** 平坦区压噪过猛 + 把柔和光影 ΔL 当成强边切断扩散 → 阴影阶跃成硬带。  
- **改动：** 场图拆成 `lumG`（明度）与 `chrG`（色度）；  
  - 真平坦 → `flatStrength`（仍抑杂色）  
  - **光影缓变**（ΔL 高、Δchroma 低）→ `shadeStrength`（加强 FS 混中间调）  
  - 结构边（Δchroma 高）→ `edgeStrength` + 仅此时 `edgeCut`  
- 暗部肤色 hue lock / slack 略放宽，便于同色相族内多档 L 参与抖动。  
- **验收：** 脸侧阴影是否仍「一刀切」；平坦脸颊是否仍明显比经典 FS 干净。

### 0.3.0-fs-v2 · 2026-10-22 · 色相杂色 / 阴影阶

- **皮肤误差塑形：** 扩散保留明度误差，压低 a/b（`skinChromaBleed`）→ 阴影仍可混 L 阶，近看少粉/灰/绿碎点。  
- **误差钳位** `errorClamp`：抑制误差爆冲导致的脏色蹦点。  
- **平坦粘滞：** 左/上邻珠若代价接近则沿用（`stickyFlat`）。  
- **色预算保肤色 L 梯：** 强制保留约 35% 槽位给按 L 抽样的肤色珠，避免中间调被预算砍光。  
- 去碎点跳过源图高对比/结构格。  
- **验收：** 脸颊杂色是否再降；阴影是否仍有中间档而非硬带。

### 0.4.0-fs-v2 · 2026-10-22 · 平坦色度预平滑 + 特征保护

- **平坦肤色 chroma smooth：** 仅在低 ΔL/低 Δchroma 肤区对 ab 做 3×3 均值、保留 L，再进 FS → 从源头少色相盐点。  
- **特征保护：** 唇色 / 暗结构坑（瞳孔等）→ 不 sticky、不去碎点、较高 `featureBleed`，避免嘴/眼被邻肤色吞成一块。  
- **验收：** 脸颊是否更匀；唇线/瞳孔是否比 0.3 更清晰且未回到全图噪点。

### 0.5.0-fs-v2 · 2026-10-22 · 对齐经典 FS 顺滑度

- **对照问题：** V2 嘴、左脸阴影、右脸高光均不如经典 FS 顺滑（压噪过猛）。  
- **改动：** shade/highlight 默认强度 ≥ 经典（0.85～0.9）；`skinChromaBleed` 提到 0.55；`edgeCut` 减轻。  
- chromaSmooth / sticky **只作用于深平坦**；高光(L↑)/暗肤(L↓)强制 `shadeStrength`。  
- 唇及邻域：近经典 `featureBleed` + 禁止 sticky。  
- hueLock 降到 0.35，减少假硬边。  
- **验收：** 同图对照经典 FS — 嘴边、额侧阴影、颊高光过渡应接近或略干净，不再明显更硬。

### 0.6.0-fs-v2 · 2026-10-22 · 卡通连接点跳色

#### 现象怎么来的（Keroppi / 18 色类）

原图是大色块 + 黑描边，但管线里会先 **缩放**（且常开 smooth），黑/白、粉/绿交界出现 **抗锯齿灰泥色**。  
FS 再把这些中间色「拆」成色板里碰巧接近的珠（粉、蓝灰、棕……），误差还推到邻格 → **描边和色块交界跳色**。  
色板 18 色里若含大量原图没有的色，脏边更容易「借」到错误珠。这与人像光影问题不同，是 **平面稿 × 抖动** 的典型失败。

#### 改动

- `detectFlatArt`：少色主导 → 自动 `flat` 模式。  
- `snapEdgeFringes`：高梯度格吸附 3×3 众数，去掉 AA 脏边（flat 跑两遍）。  
- flat 模式：近乎关闭扩散、加强 sticky / 去碎点，不做肤色逻辑。  
- `contentMode`: `auto` | `photo` | `flat`。  

#### 验收

卡通：黑描边两侧不应再撒粉/蓝碎点；色块交界干净。人像（photo/auto 非 flat）不应被误判成 flat。

### 0.7.0-fs-v2 · 2026-10-22 · 平面稿整条管线接线

- **关键：** 仅在量化里 flat 不够——若缩图仍开 smooth，硬色块也会跳色。  
- **perler `render()`：**  
  1. 用 **最近邻 probe**（96 边）`detectFlatArt`  
  2. 平面稿 → `fitImageToSquare(..., smooth:false)`，并跳过对比度/饱和度  
  3. 非 handlike 时强制 `FGBeadFsV2` + `contentMode:'flat'`（关抖动也会走吸附，不再只靠经典 nearest）  
  4. 人像选 FS V2 时显式 `contentMode:'photo'`，避免误用 flat  
- 提示文案 `perler.tip.flatArt`。  
- **验收：** Keroppi + 18 色：描边交界明显干净于「仅关抖动」；真人照片不被当成 flat。

### 0.7.1-fs-v2 · 2026-10-22 · 平面模式零扩散 + 吸附门槛

- flat overrides：`strength` / bleed / `errorClamp` 全 **0**（残余 FS 仍会在描边撒第三色）。  
- `snapEdgeFringes`：默认票数 4→可配；flat 用 **3**（黑|白 AA 常 4+4 对半分，5 票过严）。  
- **验收：** 合成硬边 + 粉泥 fringe → 量化后 fringe 落在两侧主色；噪点「照片」仍 `detectFlatArt === false`。

### 0.8.0-fs-v2 · 2026-10-22 · 描边保墨（修 Keroppi 黑线被吃）

- **根因：**  
  1. 旧 `snapEdgeFringes` 众数吸附会把 **细黑描边** 吃进黄/绿色块 → 轮廓发虚。  
  2. AA 卡通 `unique` 偏高 → `detectFlatArt` 失败，仍走经典 FS → 面内椒盐抖动。  
- **改动：**  
  - `detectFlatArt`：用 top4/top8 占比，容忍更多 AA bin。  
  - flat 改用 `resolveFlatFringes`：**墨|填二元**（暗侧保/推墨，亮侧贴主色），禁止第三种灰泥。  
  - 量化后 `reinforceFlatInk` + `flattenSolidIslands`；去碎点不删墨色。  
  - sticky 更松；暗结构边强制偏色板最深墨。  
- **验收：** 细黑线 1px 全保留；粉泥 fringe 几乎只落墨/填；AA 卡通能识别；噪点图仍非 flat。用户侧：硬刷新后 Keroppi 应出现平面提示，外轮廓黑线可读。

### 0.9.0-fs-v2 · 2026-10-22 · 三目标分区（换思路）

- **合同重写：** 只保留「强化线条 / 去抖动色 / 平顺过渡色」。  
- **实现：** `classifyRegion` → `LINE` | `FLAT` | `SHADE`，强度 / 粘滞 / 保墨按区执行。  
- **修正：** 平面稿不再把 `shadeStrength` 也打成 0（否则伤目标 3）；卡通只是更偏 LINE+FLAT。  
- **LINE：** `resolveFlatFringes` + 暗边推墨 + 跨边扩散近切断。  
- **FLAT：** strength≈0、强 sticky、去碎点。  
- **SHADE：** strength≈0.9、高 bleed，专管阴影高光。  
- **验收：** 对照三点，不再对照「检测是否 flat」。

### 0.9.1-fs-v2 · 2026-10-22 · 线条归拢（商业化）

- **诉求：** 方向已对，但描边里仍夹黄/橄榄绿/灰泥，断线未补全。  
- **`consolidateLines`：**  
  1. 轴对称墨缝补 1 格（ink—gap—ink）  
  2. ≥2 墨邻且非大色块 → 吸入墨  
  3. 贴墨的暗色 / 孤点 / 低彩泥 → 墨  
  4. 贴墨的亮脏色 → 邻域主填色  
  5. 近墨色号统一到最深墨  
- `reinforceFlatInk`：贴墨且 L&lt;55 直接推墨。  
- **验收：** 黑描边连续、线内无第三色；腮红/色块边界不被整圈加粗成墨。

### 0.9.2-fs-v2 · 2026-10-22 · 归拢回退（防过修）

- **现象：** 0.9.1 把贴墨的黄/粉/绿也吞进黑，暗部整块变黑洞，特征碎成色岛。  
- **回退：**  
  - `isInkLab` 收紧（L≤28 / 近墨 ΔE 小）  
  - **永不**把 `isChromaticFill`（黄粉绿等）推进墨  
  - `consolidateLines` 只补灰泥断缝 + 低彩孤点；遍数降为 1  
  - 去掉「L&lt;55 贴墨即墨」  
- **验收：** 接近 0.9.0 可用度，线条略净于 0.9.0，但不出现大块特征被黑吃掉。
